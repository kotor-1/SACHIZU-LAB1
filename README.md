# SACHIZU LAB — CMJ / RJ / 10m

無料のブラウザ用・公開テスト版です。動画は端末内で解析し、アプリからサーバーへアップロードしません。個人動画・解析結果・選手データ・非公開の学習モデルはこのリポジトリに含みません。

このサイトは CMJ・RJ・10m の3種目だけです。陸上競技の動作解析（ハードル・跳躍・投てきなど）は含みません。

- CMJ：録画またはカメラから跳躍高を推定。左右のつま先が床から離れる瞬間と、空中の重心の最高点までの時間で計算します（ライブv7）。姿勢モデルはライブ・録画ともFull。PUSHなど他の機器とは基準が異なり、低めに出ます。
- RJ：両足RJの録画から平均RSIを推定。つま先の軌跡で周期を区切り、靴底の画像で離地・着地を測ります（靴底接地v1）。身長・基準物・コマの手動指定は不要。`?lab=rj`（以前の `?lab=rj-toe-cycle` も同じ画面）。
- 10m：スタート・ゴールの2本の線を設定するだけで、通過時間・平均速度・歩数・ピッチ・平均歩幅・各歩の距離を推定（v6）。

## ローカル実行

Node.js 22以降で `npm ci`、`npm run dev` を実行し、表示されたURLの `/SACHIZU-LAB1/` を開きます。`npm test` で回帰テスト、`npm run build` で公開用ビルド、`npm run preview` で確認できます。

## 計測の制約

RJに「FullとHeavyを比較」を追加しました。同じ元動画・全フレームをFull→Heavyの順に処理し、RSI計算側を固定して比較します。通常解析はFullのままです。Heavyは初回約30MBの受信があり、数分以上かかる場合があります。画面を開いたまま待ち、比較完了後に両モデルの採用回数・追跡率・処理時間を確認し、比較JSONを保存できます。高いRSIや多い採用回数は精度の保証ではありません。RTMPose/RTMWの比較はまだ含みません。

RJ自動解析v3は、合格した9条件（3つの画素閾値×3つの時間窓）の時刻の中央値を使用します。特定の1条件だけの時刻に依存しないための修正で、合格基準の緩和ではありません。端末間の一致や実測精度を保証するものではなく、採用された回が違う平均同士の比較には注意してください。

研究・試験機能で、測定器同等の精度は未検証です。表示が出ることと精度が確認されたことは異なります。医療・競技公式判定用ではありません。

スマホを固定し、明るい場所で全身・足元を映してください。録画は元のフレームと通常の時間軸を保持してください。スロー書き出し倍率は自動補正しません。RJは撮影条件によって採用回数や値が変わります。10mの距離換算は横に近い固定撮影を前提とし、接地点間の実測ストライドではありません。

MOV/MP4の元フレーム解析はWebCodecs対応とコーデック対応が必要です。iPhone・Android全機種での動作は未検証です。端末性能により待ち時間が変わります。モデルの初回読み込みには通信が必要です。

CMJは正面撮影を推奨します。横向きで奥側の関節が隠れる動画は、骨格が一部表示されても全身重心の条件を満たせず結果が出ない場合があります。不鮮明なコマは同じ元フレームの人物領域を再推定しますが、前後のコマによる補間や信頼度基準の緩和はしません。解析に失敗したときは「解析できない原因を保存」で診断情報を保存できます。

## プライバシーと保存

CMJの小さいジャンプには、従来の計算が成立しない場合に短い空中区間を使う試験的推定を追加しています。5cm・60fps、10〜15cm・30fpsの合成波形による動作テストであり、児童の実測精度を保証しません。観測不足や不安定な推定では高さを表示しません。スマホは腰付近の高さで固定し、跳躍中も全身が収まるようにします。「録画も残す」は任意で、オンの場合のみ最長20秒で停止します。

会員登録・広告・アクセス解析なし。動画・手動登録・解析結果はブラウザ内で処理します。必要な結果はJSON/CSVの保存ボタンで保存してください。ページを閉じると未保存の結果は失われます。サイト配信時のIP等はGitHubが処理する場合があります：[GitHubプライバシーポリシー](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement)。

## CMJ ライブv6：ジャンプ前のカウントダウン

カメラ起動後、全身を映して静止すると「3・2・1 → ジャンプ」の合図が出ます。合図前は動作を結果として収集せず、姿勢の確認を続けます。追跡欠落や姿勢変化でカウントをやり直し、各動作後も再準備します。停止・画面非表示・再開始で前のカウントを引き継ぎません。任意の録画は最初のカウント開始から保存します。高さの推定式・候補選択は変更していません。

## CMJ ライブv7：つま先の離地＋重心の最高点

ライブ・録画のCMJの高さを、重心の形だけで離地を推定していた旧方式から切り替えました。左右のつま先が床から浮き始める瞬間を前後のコマへの当てはめでコマ間の時刻まで求め、両足が空中にある間の重心の放物線の最高点までの時間から、`h = g/2 × t²` で計算します。身長入力・参照値への補正はありません。同じ240fps動画を30〜120fpsに間引いても、スマホのライブのような不規則なコマ間隔にしても、約1.5cm以内で同じ値になることを確認しました（旧方式は同じ動画で41.7cm、新方式32.8cm）。足先と床が映らない場合、毎秒約17コマ未満の場合は数値を保留します。姿勢モデルはライブ・録画ともMediaPipe Full（軽量モデルへの自動切り替えなし）です。PUSHなど他の機器とは基準が異なり、低めに出ます。アプリ内の記録どうしで比べてください。iPhone実機のLiteモデル、力板などの独立基準との比較は未検証です。

## 両足RJ（つま先軌跡）：靴底で離地・着地を測定（靴底接地 v1）

`?lab=rj-toe-cycle` の平均RSIを、つま先の型だけの推定から、靴底の画像で測った離地・着地による計算に変えました。つま先の骨格点は、踵が上がって足が靴の先で回転し始めると、靴がまだ床に着いていても上がるため、型は離地を早く取り、接地時間を短く・RSIを高く出していました（40周期の目視確認で平均約1.3コマ早い）。姿勢推定と同じ1回の読み込みで足元の小さな範囲だけ靴の輪郭を調べ、靴底が速く上がり始めた瞬間を離地、速い下降が止まった瞬間を着地とします。つま先で押している間のゆっくりした転がりは離地に数えません。靴底を確認できない周期は型の値で補わず、3周期未満なら保留します。保存JSONには靴底データも保存され、再計算に使えます（靴底データのない古いJSONでは平均RSIを表示しません）。頂点選択v4（前後の両足軌跡を確認）も同時に反映しています。2026-09-30から、ホームの「RJ」もこの方式です（以前の自動RJの画面は公開サイトから外しました）。精度は未検証で、PUSHなど他の機器とは定義・集計が異なります。

## 10m スプリント v6：最初の1歩の入力を廃止・歩数の誤計数を修正

`?lab=sprint10` の手順を「動画 → 再生確認 → 2本の線 → 解析」にしました。これまでの「最初の1歩（左右・接地コマ）」の入力は、スタート側の半端な1歩を数えるかどうかだけを決めており、タイム・速度には使われていなかったため廃止しました。歩数は、2本の線の間に経過した脚の入れ替わり周期の数で、線上の半端な周期は割合で数えます（例：7.3歩）。スタートとゴールは同じ規則です。ピッチと平均歩幅もこの歩数から出します。姿勢推定が1〜2コマだけ両足首を同じ脚に置く誤りで1歩多く数えていた不具合も直しました（足首間隔の平滑化を前後25msに変更）。タイムは骨盤中心の通過間隔で、線はコース上（選手と同じ奥行き）の目印に合わせてください。手動計測との照合は未実施です。
