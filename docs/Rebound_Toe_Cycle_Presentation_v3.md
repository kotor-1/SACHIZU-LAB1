# つま先軌跡RJ：候補幅の表示・保存骨格の再計算

2026-09-26。これは表示・入出力の変更であり、RSI精度改善版ではない。
`rj-toe-constrained-cycle-v2-research` の式・係数・品質条件・採否・平均は変更しない。
通常RJ・CMJ・10mの解析ソースにも変更を加えない。

## 変更

- 単一の最適値を大きく出す表示から、既存のモデル設定に依存する候補幅を主表示にする。
- 最適候補の平均は「参考」として併記する。各周期にも候補幅と参考値を表示する。
- 候補幅は各採用周期の下限・上限をそれぞれ平均したもの。信頼区間、真値が含まれる保証、誤差上限ではない。位相・足の変形など全ての誤差要因を網羅しない。
- 「全周期を計算できた」と「正確さを確認した」を区別する。年齢・人物・期待RSIによる補正はしない。
- 以前保存した `rebound-toe-cycle.json` の骨格を読み込み、動画デコード・姿勢推論をせず現行式を再計算できる。保存されたRSI・以前の比較値は計算に使わない。

## 入出力と安全性

- outer exportは `rj-toe-cycle-export-v1`、数値モデルはv2のまま。表示識別子だけ `rj-toe-cycle-presentation-v3` を追加。
- JSON入力は32MiB以下、1〜3600コマ、30秒以内、連番frame・厳密増加PTS、各人物33点の有限座標、可視性0〜1を検査。空人物・2人物のコマはそのまま保持し、元の対象人物検査に渡す。
- 画面外の正規化座標、負のz、低可視性点は変更しない。欠測を補間せず、コマを削除・並べ替えしない。
- JSON内のハッシュは申告識別子にすぎない。元映像を再照合していないため、画面にも非照合と表示。再出力の `inputProvenance` は `SAVED_JSON / sourceVideoVerified:false`。保存値の自己申告を信用してtrueに昇格させない。
- 動画を直接読んだ場合は `VIDEO / sourceVideoVerified:true`。ここでのverifiedは読み込んだ動画からハッシュと骨格を取得したことだけで、計測精度の認証ではない。
- 動画・JSONの切替時、および不正JSON読込時には旧結果とキャッシュを消す。JSONだけでは映像再生や骨格の目視照合はできない。
- ブラウザ内の処理のみ。動画や骨格JSONを外部へ送信しない。

## 操作

1. 専用試験画面 `?lab=rj-toe-cycle` を開く。
2. 「保存済みJSONから再計算」で以前のつま先軌跡JSONを選ぶ。
3. 「入力なしでRJを解析」を押す。骨格再取得なしと表示される。
4. 候補幅、参考値、周期数を確認し、必要なら再保存する。

同じ骨格・同じモデルなら同じ数値になることが期待される。これは再現性の検査で、予測精度の証明ではない。数値精度の問題は未解決。

- 全体171ファイル・3017テスト、公開用27ファイル・288テスト、型検査・公開ビルドが通過。
- 元動画の開発Chromeと公開用ビルドのデスクトップWebKitで、動画入力・骨格再生・JSON保存・同じ骨格からの再計算一致・リセット・動画取得中の停止・320/390/1280px表示を確認。
- 保存JSONの読込検査では69件の境界・形式テストを追加。既存結果や自己申告の照合状態を破棄し、骨格からのみ計算する。

- モデル計算自体は既存の同期処理。計算関数の実行中まで即時停止できる実装ではない。
